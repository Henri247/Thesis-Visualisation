BUILD PROCESS

Built with AI. Checked against the research.

The project began without a software-development background. AI is used as a development partner for structuring, prototyping, coding and debugging — not as a substitute for source verification or analytical judgement.

01Read

Extract chapter structure, case-study claims and methodological limits from the dissertations.

02Structure

Convert research material into routes, evidence objects, themes and interface components.

03Prototype

Generate HTML, CSS and JavaScript, then test information architecture and interactions.

04Verify

Keep evidence attached to dissertation pages and cited sources; avoid invented quantitative scoring.

05Debug

Use AI to identify broken paths, layout problems, map behaviour and mobile issues.

06Deploy

Publish a static site on GitHub Pages with version history visible in the repository.

07Iterate

Improve the visual language, evidence interface and narrative based on real use.

08Explain

Document what AI did, what the human decided and how outputs were checked.

EXAMPLE WORKFLOW

SOURCE PDF ↓ extract research claim + page ↓ structure as JSON ↓ design component ↓ generate / revise code ↓ test interaction ↓ human check against dissertation ↓ commit to GitHub

WHAT THIS PROJECT EVIDENCES

AI proficiency is the workflow, not the claim.

The repository shows the artefact, structured data, iteration history and documentation that make the process inspectable.
